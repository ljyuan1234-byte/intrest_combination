# 数据治理与安全

版本：V0.1  
原则：收集最少必要数据，明确用途，用户可查看、导出和删除。

## 1. 数据分级

| 等级 | 数据 | 处理要求 |
|---|---|---|
| L0 | Mini App 公共配置、非敏感偏好 | 普通访问控制 |
| L1 | 任务、日程、娱乐设置 | 按用户隔离，记录变更 |
| L2 | 消费记录、健康记录、饮食偏好 | 加强访问控制、脱敏日志、按需传给模型 |
| L3 | 认证凭据、第三方授权 Token、支付信息 | 首期不保存；未来必须使用 Secret Manager 和短期授权 |

## 2. 数据生命周期

- 业务数据：用户主动删除前保留。
- 对话消息：默认保留一段可配置周期，允许用户清空；不自动永久保存全部上下文。
- Agent 运行日志：保存摘要、工具、耗时、状态和成本；原始敏感输入按最短必要周期保存。
- 上传原文件：导入确认后按配置周期删除，结构化结果单独管理。
- 审计日志：不能由普通业务删除，按安全和运维策略保留。
- 备份：加密保存，删除请求在备份自然过期后完成最终清除。

具体天数在正式部署前通过配置确定，并在产品隐私说明中公开。

## 3. 访问和加密

- 所有业务查询从当前会话获取 `user_id`。
- 服务端不能信任客户端传来的用户身份字段。
- 传输使用 HTTPS；本地开发允许 HTTP。
- 数据库连接使用 Secret Manager 管理的凭据。
- L2 数据可以在应用层加密；加密密钥与数据分离保存。
- 文件使用随机对象键和短期签名 URL。
- 日志不得出现密码、Token、完整健康原文或完整账单明细。

## 4. 导入文件安全

- 限制扩展名、MIME、文件大小和行数。
- 解析前检查文件类型，不根据文件名判断格式。
- 文件内容当作不可信输入，不能执行其中的宏、脚本或指令。
- 导入采用预览和用户确认两阶段。
- 导入任务设置超时、资源上限和失败清理。

## 5. 用户权利

首期必须提供：

- 查看个人数据。
- 导出结构化数据。
- 删除记录。
- 清空对话和长期记忆。
- 撤销通知设备。
- 删除全部账户数据。

## 6. 审计事件

至少审计以下行为：

- 登录、退出和会话撤销。
- 数据导入、确认、失败和回滚。
- Agent 工具调用及结果状态。
- 审批创建、批准、拒绝、过期和执行。
- 连接器授权、撤销和失败。
- 数据导出和全量删除。

审计日志只记录完成追踪所需的信息，不复制敏感业务内容。

## 7. 事件响应

发现疑似泄露或越权时：

1. 立即撤销相关会话、设备或外部授权。
2. 暂停受影响工具和连接器。
3. 保留审计证据，避免覆盖日志。
4. 判断影响的数据范围。
5. 修复后进行回归测试和密钥轮换。
