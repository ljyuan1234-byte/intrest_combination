# 产品需求与范围

版本：V0.1  
状态：讨论基线  
目标：为个人提供一个能长期积累数据、通过 Agent 提供建议、并可在 Android 和电脑 Web 上访问的生活助手。

## 1. 产品定位

这是一个个人云端生活工作台，不是单纯聊天机器人，也不是自动替用户操作所有账号的机器人。

核心闭环：

```text
记录生活数据 -> 看见状态 -> 获得建议 -> 用户确认 -> 形成下一步行动 -> 持续记录
```

产品必须让结构化数据和建议可追踪。重要信息不能只存在对话气泡里。

## 2. 用户和平台

- 首期用户：单个个人用户。
- 首期平台：Android App、桌面浏览器 Web。
- 首期地区：中国大陆。
- 首期通知：Android 推送和 Web Push，不依赖微信。
- 首期部署：云端托管。
- 后续方向：可以扩展家庭成员、更多客户端和外部连接器，但不纳入 MVP。

## 3. MVP 目标

用户可以：

1. 记录和管理待办、日程和提醒。
2. 手动录入或上传步数、睡眠、饮水、体重和锻炼信息。
3. 获取基于已记录信息的每日饮食和锻炼建议。
4. 手动记录消费，并查看分类和月度汇总。
5. 通过自然语言查询自己的日程、健康摘要和消费统计。
6. 使用娱乐/传统文化 Mini App。
7. 看到所有 Agent 建议的依据、生成时间和确认状态。

## 4. MVP 功能范围

### P0：必须具备

- 个人账号和登录会话。
- 今日首页。
- 待办创建、完成、编辑和删除。
- 日程记录和提醒配置。
- Android 推送和 Web Push 的通知设置。
- 健康数据手动录入。
- 健康文件上传、预览、确认导入。
- 饮食建议和锻炼建议。
- 手动记账、分类、月度汇总。
- Agent 只读查询和建议卡片。
- 数据导出、删除和基本审计日志。

### P1：MVP 后优先

- ICS 日程导入。
- 更完善的健康趋势图表。
- 预算设置和消费提醒。
- 用户主动保存的偏好记忆。
- 传统文化排盘和历法工具。
- 票务信息查询和提醒。

### P2：长期探索

- 12306 和大麦等平台的网页/Android 页面辅助操作，前提是平台规则允许且用户主动启动。
- 官方授权的外部连接器。
- 家庭共享空间。
- Agent 草稿经确认后写入内部模块。
- 官方允许范围内的票务流程自动化。
- 经审核、签名和沙箱隔离的第三方 Mini App。

## 5. 明确不做

- 不做医疗诊断、处方、停药或紧急处置判断。
- 不做投资建议、自动转账或支付操作。
- 不做微信通知依赖。
- 不接入手机健康平台或穿戴设备的自动采集。
- 不保存第三方平台明文密码、支付密钥或浏览器凭据。
- 不绕过验证码、人机验证、登录保护或平台风控。
- 不在云端远程控制用户浏览器或 Android App。
- 不允许 Agent 任意执行电脑命令、访问任意文件或发送外部消息。
- 不允许未经审核的插件代码在主进程执行。

## 6. 关键用户故事

### 日程和任务

- 作为用户，我可以写下“周五晚上提醒我买水”，系统生成待办草稿供我确认。
- 作为用户，我可以查看今天的任务和日程，并收到我主动配置的提醒。

### 健康

- 作为用户，我可以上传一份包含步数、睡眠或饮水数据的文件，并在导入前看到解析结果。
- 作为用户，我可以告诉助手今天吃了什么、做了什么运动，获得生活方式建议。
- 作为用户，我可以看到建议依据的是哪段时间、哪些数据。

### 财务

- 作为用户，我可以快速录入一笔消费、金额、日期和分类。
- 作为用户，我可以查看本月各分类支出，并要求 Agent 做总结。

### 娱乐和传统文化

- 作为用户，我可以打开星座、天干地支、五行八卦等工具。
- 作为用户，我能明确知道这些内容是娱乐或传统文化展示，不是事实预测或专业决策依据。

### 票务辅助

- 作为用户，我可以在 Android 或 Web 上配置 12306、演出平台的搜索条件和偏好。
- 作为用户，我可以主动启动本地页面辅助任务，查看可选车次、场次、价格或席位。
- 作为用户，我可以在验证码、订单提交和支付前接管操作。
- 作为用户，我可以随时停止任务，并查看任务状态和操作摘要。

## 7. MVP 验收标准

- 新用户完成首次登录后，可以在 3 分钟内创建第一条待办和第一笔消费。
- 健康上传失败时，不会产生半条或重复记录；用户能看到错误原因。
- Agent 不调用未授权工具，不将健康和财务原始数据写入长期记忆。
- 所有 Agent 生成的草稿都有明确的“待确认”状态。
- 删除用户数据后，业务数据库、对象存储和索引中不再保留可恢复副本，备份按规定周期过期。
- Android 和 Web 使用同一套 API 契约，关键数据刷新后能保持一致。
